# 留白 · 日程规划 APP

计划被打乱时，帮你安排好接下来。

[项目仓库](https://github.com/LikLiiik/Liubai) · [手机试用反馈](https://github.com/LikLiiik/Liubai/issues/new/choose) · [自动检查](https://github.com/LikLiiik/Liubai/actions)

第一版实现放在 `mobile/`，使用 TypeScript、React Native、Expo SDK 58 和 Expo Router。网页是同一套 APP 的预览入口，手机端使用 SQLite 保存数据，网页端使用浏览器本地存储。

当前开发修正（尚未打包）：新手教程直接展示可分别填写小时、分钟的双滚轮；周览练习复用正式任务卡片与 15 分钟吸附规则，可以实际拖动调整时间及日期。示例数据独立于个人日程。已发布的 0.3.0 APK 仍是上一版教程。

## 已实现

- 今天：时间轴、今日重点、时间预算、完成/恢复任务。
- 周览：课程表式周一到周日网格、切换周次、自适应/大卡片、全天范围；行高按屏幕可用高度调整，全天通过上下滚动查看。任务可跨天拖动，按 15 分钟吸附，边缘拖动会自动滚动。
- 固定事项默认锁定，二次确认后解锁一次拖动，松手后重新锁定；也可精确填写日期、时间。固定事项直接改时间时会确认目标位置。跨午夜事项在次日接续显示，拖动任一段会整体移动；手动重叠安排确认后可保存，超过硬截止日期的移动仍会被拒绝。有效移动写入回顾，可撤销。
- 手动并行安排：新增、编辑或周览调整时，同一时段可保留多件事，重叠前显示涉及事项并确认；取消保留原安排，周览中并排展示。授权只对本次位置和涉及事项生效，自动排程不会因此获得重叠权限。

周览以表格为主体，顶部只保留一行工具栏；说明、统计与显示选项收进右上角菜单，待安排任务默认收起。时间轴始终覆盖 00:00–24:00，浅灰区域表示偏好时段之外。手动拖动或精确改时间超出偏好时段时，确认后才会保存，取消则保留原位置；授权只对这次移动生效，自动排程继续遵循用户偏好。在“周览显示选项”中可切换大卡片，点击顶部收集箱图标展开待安排任务。网页可直接拖动，手机原生端长按后拖动；点击卡片也可精确填写日期与开始时间。原生手势仍需真机验收。
- 探索：统一提供收集箱与回顾两个入口；进入子页面后仍选中探索，并可从顶部返回。
- 收集箱：任务分类、未来任务、之前未完成的任务、安排到今天。
- 任务管理：新增、编辑、删除、备注、预计时长、固定时间、优先级、截止日期。
- 一键救场：临时有事、确认任务剩余时长、低精力模式、直接重新安排。
- 取舍预览：保截止时间、保结束时间、保今日重点；查看任务变化、延期和冲突后再套用。
- 回顾：完成记录、调整足迹、撤销最近一次调整。若之后又改了任务，会阻止整批撤销，避免覆盖修改。
- 我的：日程偏好、灵活任务之间的缓冲、提醒、导出 JSON 数据、重看新手教程。原偏好设置链接会转到我的。
- 我的 → 课表导入：哈工大（深圳）本科课表的教务读取、学期日期确认、课程选择、冲突预览和确认导入。课程生成固定事项，支持单双周、不连续周次、特殊课程延后 15 分钟、去重、合并更新和同步移除；手动修改与已完成记录受保护。示例仅在新手指引内演示，学校真实登录与当前接口仍需手机联调。
- 偏好时间支持 `9`、`930`、`9点半`、`晚上11点` 等常见写法，离开输入框后自动补全；结束时间提供快捷选项，最晚可选次日 06:00。自动排程会使用跨夜时段，午夜后继续上一晚的安排；任务日期按实际日历保存，硬截止仍以截止日午夜为界。
- 手机本地通知的权限与排程接入；示例数据不会触发通知。通知需要真机验证。
- 收集箱空闲提醒：有安排的日子也会按连续空档推荐待办。我的中可独立开启，设置 30–120 分钟的连续空闲阈值；每天最多一条，用户确认后才安排，可暂缓该待办 3 天。
- 我的 → 检查更新：读取已发布版本、更新说明和安装包大小；Android 有新版时可直接打开下载，网页可获取最新安卓安装包。支持检查失败重试，不推荐降级。
- 常驻新手指引：首次使用自动进入 8 步教程，涵盖核心操作、独立教学演示、通知权限、更新和备份；支持稍后再看、继续和重看，在“我的”顶部长期保留入口。
- 统一时间控件：日程开始、偏好起止，以及任务、救场、缓冲、空闲提醒的时长均可直接填写，也可展开小时和分钟双滚轮，逐分钟选择。时长输入支持分钟数、时分和中文单位；显示统一为时分，结束偏好继续支持次日 06:00。

首次打开会显示新手教程，示例仅存在于教程的独立教学卡片中，不写入个人日程。完成教程直接进入“今天”，首次使用从空白日程与真实时间开始；退出、重看或完成教程均不清空已有任务、偏好和提醒设置。旧版未改动的默认示例会自动转为空白个人日程；有新增、修改或调整记录时保留全部任务，避免丢失个人工作。

## 运行

环境：Node.js 24 LTS，npm。

```powershell
cd D:\日程规划APP\mobile
npm ci
npm run web
```

查看构建后的网页预览：

```powershell
npm run build:web
npm run preview
```

打开 http://127.0.0.1:4173 。预览服务只监听本机，不会公开发布。若端口占用，可先设置 `$env:PORT='4179'` 再启动；本次已打开的预览地址为 http://127.0.0.1:4179 。

手机开发：

```powershell
npm start
```

在匹配 SDK 58 的 Expo Go 中预览其支持的功能。完整原生验证需要开发包或安装包。

## 新手指引与持续维护

首次使用自动展示 8 步教程：记录任务、周览调整、一键救场、探索中的收集箱与回顾、个人偏好与课表、通知权限、更新备份及开始真实使用。“我的”顶部提供继续/重看入口，另可直达“通知与后台设置”。教程允许中途退出，稍后再看会记住当前位置并停止本轮自动弹出；完成后仍可从头重看。教学卡片使用独立状态，救场演示调用实际排程规则，但不会套用到真实任务。

进度使用独立的 `liubai.guide.v1` 键，手机保存在 SQLite，网页保存在本地存储，不随清空任务而丢失。保存失败时显示重试入口，不阻止继续使用。教程中的通知权限仅在用户点击后申请，可分别启用任务开始提醒和收集箱空闲提醒；拒绝后能继续教程，不可再次申请时引导去系统设置。回到前台重新检查权限，用户已选择开启的提醒会在允许后保存。Android 还提供通知、后台运行和电池管理说明及应用设置入口，不擅自更改系统选项。网页不请求手机权限。

教程内容与修订号集中在 `mobile/src/guide.ts`，稳定步骤 ID 用于进度迁移；教学演示在 `GuideLessons.tsx` 与 `GuideWeekLesson.tsx`。新增核心功能、路径或权限时，同步更新对应教程，必要时递增 `GUIDE_REVISION` 并为更新步骤设置 `introduced` 修订号，让已有用户从更新内容开始；仅修改应用版本号不重放教程。这一维护要求已写入 `mobile/AGENTS.md`。

## 检查更新与发布

发布流程由版本化元数据驱动：构建成品通过 `scripts/verify-apk.py` 校验包名、版本号、ZIP CRC、Hermes 资源、原生库、APK v2 签名与上一版签名连续性，再登记到 `releases/versions/<版本>.json`。推送版本标签后，GitHub Actions 先执行项目检查，再校验下载成品的字节数和 SHA-256，上传 APK、校验文件和更新记录，全部成功才公开 Release。已公开的不同资产不自动覆盖。最后验证公开下载并更新客户端使用的 `releases/android-release.json`；更新源不会提前指向未完成构建。

入口位于“我的 → 应用更新 → 检查更新”。仅在点击后联网读取本仓库 `main` 分支的 `releases/android-release.json`，不发送任务、偏好或登录凭证。对版本号按数字比较，Android 同版本时也比较可读取的构建号。开发版本高于已发布版本时不会显示降级下载；网页提供最新已发布安卓包的下载入口，iOS 不会显示 APK 安装按钮。连接或响应超过 12 秒会提示重试，离开页面则取消检查。

发布记录是客户端的更新源，开发中的 `app.json` 版本号、Git 标签或构建中的任务不会自动成为更新。每次用户明确要求统一打包后，再构建并校验 APK，确认包名和原签名，上传可下载的成品，最后更新并推送 `releases/android-release.json`。保留 `version`、`androidVersionCode`、`package`、`file`、`sizeBytes`、`sha256`、`downloadUrl` 和已通过的 `checks.archiveCrc/package/embeddedBundle`，可追加纯文本 `notes` 更新说明。下载地址支持本仓库 GitHub Release 的 HTTPS APK 资产及现有 Expo APK 链接，长期发布优先使用 GitHub Release 资产。

用户点击“下载更新”后通过系统浏览器下载，由安卓系统确认安装，不在应用内静默安装。SHA-256 在发布时记录并检查格式，当前下载交给浏览器，客户端不声称已校验用户下载文件。当前发布源指向 GitHub 的 0.3.0 APK，公开下载文件已完整下载并校验；手机版浏览器交接及覆盖安装仍需真机测试。

## 收集箱空闲提醒

入口为“我的 → 收集箱空闲提醒”，与日程开始提醒分别控制。默认连续空闲至少 1 小时，可填写或滑动选择 30–120 分钟。按偏好时段查找完整空档，已有课程和其他事项都作为占用，灵活事项保留切换缓冲；不要求整天没有任务，也不把零碎空闲相加。推荐未完成且未安排的收集箱任务，并检查任务时长、硬截止和暂缓日期。

开启通知后，手机预先登记未来 7 天的本地提醒；日程或偏好变更、日期切换和回到应用前台时重新计算，取消失效的预约。每天最多一条，候选任务会轮换；频次记录在登记系统通知前持久化，重启后不重复提交当天已到时的提醒。通知点击后打开确认弹窗，再次检查当前日程；只有点击“安排这件事”才写入任务，并可在回顾撤销。选择“暂不安排”后，该任务 3 天后恢复推荐。

网页与教程示例不发送系统通知，“预览待办提醒”可检查确认与暂缓流程。此实现无需服务器推送；超过预先登记的 7 天且未再打开应用时，不会继续生成新的提醒。系统省电、通知权限和系统调度可能延迟送达；真实后台送达、冷启动点击和重启表现需安卓真机验证。

## 课表导入

入口位于“我的 → 导入课表”，目前适配哈工大（深圳）本科生。安卓中使用内置网页完成学校统一认证，用户选择学期并进入个人课表后点击“读取课表”。程序在该教务页面的会话内发送只读查询请求，预览后才写入本地日程。账号、密码、Cookie 和完整网页不传回留白，不接入代理登录服务器；内置网页使用隐私模式，关闭时停止读取并卸载网页。

当前适配以公开项目记录的 `/component/queryRlZcSj` 与 `/xszykb/queryxszykbzong` 请求协议为依据，独立实现解析和转换，没有验证学校现行登录后接口。参考：[公开适配项目](https://github.com/rewired-gh/hitsz_course_schedule_ics_converter)、[学校登录说明](https://due.hitsz.edu.cn/info/1052/8511.htm)。校外访问可能需安校通客户端；经网页代理改写的教务地址暂未适配，不绕过证书验证或访问控制。学校文档中的 HTTP 教务入口通过配置插件仅对 `jw.hitsz.edu.cn` 放行，其他域名继续禁用明文访问。

- 本科节次按[学校教务页面公布的作息](https://due.hitsz.edu.cn/info/1052/8421.htm)转换；开学日期必须为该学年的第一周周一，并由用户核对。特殊课程可分别延后 15 分钟。
- “合并更新”添加或更新课程，不移除缺失课程；调课、退课后可使用“同步本学期”，预览要移除的原课程。其他学期和个人任务不会被删除，已完成或手动修改的课程保持原记录。
- 存在时间冲突、无法解析的课表条目或无效日期时，不能确认导入。课程时间可超出日程偏好；它们作为固定课程参与后续自动排程，不会被移走。
- 课表导入写入个人日程，保留其他任务。导入记录可在“探索 → 回顾”撤销，后续已修改日程则阻止整批撤销。
- 课表解析与导入规则使用隔离的模拟教务响应测试，不请求学校账号，不能证明学校登录与当前接口已经可用。Android 原生资源编译和配置生成已验证，实际学校读取留待手机测试。

## 排程规则

固定事项与已完成事项不移动。不完整的任务即使原定时间已经过去，也不会被自动标记完成。灵活任务尽量整块安排；当前不自动拆分一个任务为多个时间块。

用户可在新增或编辑中指定固定时间，也可在周览中拖动或精确修改时间，在重叠确认中主动保留同时安排的多件事。固定事项解锁、非偏好时段和重叠安排各自需要相应授权；允许重叠也不能越过硬截止日期或移动已完成的任务。确认过程中目标时长或涉及事项发生变化时，重新确认；原有重叠任务仅改名称、备注时不重复要求重叠确认。

自动安排收集箱任务、空闲推荐、一键救场继续避开已有占用，不会套用手动重叠授权。用户已安排的固定重叠事项原样保留，其占用时间合并后供其他任务避让，不会仅因它们重叠就阻止整个排程；未固定的任务在自动重新安排时仍会分配到互不重叠的位置。教务课表批量导入保持原有冲突检查，不自动制造重叠课程。已在独立网页环境验证周览取消/确认、刷新保存、并排显示，以及新增和延长时长的重叠确认；原生拖动仍待统一打包后真机验收。

“保截止时间”允许在预览中接受最多延后结束 60 分钟，跨夜安排始终不超过次日 06:00。“保结束时间”和“保今日重点”不延长结束时间。今天或之前到期的任务放不下时会阻止套用，明确提示用户处理冲突；普通任务移到明天待安排。低精力模式把剩余可用时间的一半作为任务时长预算，不擅自缩短任务。

时间预算采用任务预计时长及灵活任务缓冲的估算，不是完成概率，也不是对连续时间块一定可用的保证。任务时长在回顾中始终标为“计划时长”，没有伪装成实际专注数据。

## 当前边界

尚未实现账号与云同步、系统日历双向同步、AI 理解与拆解、真实耗时学习。JSON 目前支持导出，尚无导入恢复界面。没有连接外部 AI 服务，也不需要 API 密钥。

111 项规则测试、代码检查、类型检查及网页构建通过；0.3.0 安卓包已生成、签名校验并公开发布，iOS 安装包尚未生成。新手流程、时间输入、刷新保存与窄屏布局已通过网页检查。手机 SQLite 和通知已经接入；原生界面、系统权限、后台通知和真实教务读取仍需真机验收。数据只保存在当前设备/浏览器，清理应用数据会移除记录。
